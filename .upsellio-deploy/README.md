# Upsellio chat integration
Production: https://upsellio.pl. Upsellio DevOps Bridge 1.2.0 is installed and active, alongside the existing Rank Math bridge.
## Setup
Open https://upsellio.pl/wp-admin/tools.php?page=upsellio-devops-bridge as administrator. Preserve the existing private 0700 backup directory. Global automatic deployment is opt-in. CRM and offer automation require separate opt-ins; both must be enabled for files shared by CRM and offers. Automatic backend deployment additionally requires GitHub branch protection on both main and upsellio-deploy. Verify trusted repository writers, required review/checks and branch restrictions before enabling. The upgrade does not turn on backend automation by itself.
## Deployment protocol
This branch carries requests only. Edit source on a feature branch, test and review, then merge approved changes into main. Read live state and exact production file SHA-256 values using page 947 in edit context (meta.upsellio_devops_status). This also reports backend_allowlist, auto, auto_crm, auto_offers, pending recovery and last request. Use a reviewed immutable commit on main and a unique 12-80 character request ID. The manifest must contain EXACTLY four keys: schema (integer 1), request_id, commit (full 40 lowercase hex SHA), files. Each file entry must contain EXACTLY path, before, after (64 lowercase hex SHA-256 strings). Do not include action in deployment manifests, or before_sha256 / after_sha256 keys. Idle is exactly {"schema":1,"action":"idle"}.
Paths are relative to wp-content/themes/upsellio. Use exact production byte hashes, including line endings. Presentation-only releases are limited to 12 files; releases with an allowlisted CRM/offer path are limited to 40 total files and a 32 KiB manifest. Existing regular writable files only; each file <=1 MiB. Backend paths are explicitly enumerated by the installed plugin; do not infer permissions from a directory prefix. For shared CRM/offer paths both automatic scopes must be enabled. No functions.php, arbitrary inc/, vendor, config, plugins, database migrations, new files or deletions. Do not include client records, credentials or unpublished offer data in this public repository.
The bridge verifies ancestry, checks current and proposed hashes, stages backups, lints PHP, uses a short maintenance window for backend swaps, verifies installed hashes, clears caches and checks homepage HTTP. Offer releases additionally require an existing offer compatibility list (upsellio_offer_legacy_payload_ids_v2); the bridge never creates or edits offer terms. No database rollback is provided. Existing companion release installers must not be used concurrently. Never override a live hash mismatch; reconcile source and re-test. Do not assume a homepage check proves CRM or offer functionality; run scoped functional and visual checks without modifying live customer data. Check final state and all installed hashes before clearing a successful manifest. Only reset request.json to idle after confirming the exact request and hashes; rollback disables automation. Do not overwrite an unrelated pending manifest.
## Manual fallback
Check GitHub, review the manifest and use Deploy reviewed manifest. This requires administrator capabilities and a nonce. The public GitHub repository is a code source, not a public write endpoint. Do not share secrets or attempt to bypass scope opt-ins.
## Rank Math
Read and write SEO fields using WordPress content-items-get/update with post_type post or page, context edit on reads, and meta containing rank_math_title, rank_math_description, rank_math_focus_keyword, rank_math_facebook_title/description and rank_math_twitter_title/description. Preserve existing unrelated content and metadata. A stored rank_math_seo_score may be available in edit responses, but never write a fabricated score; verify recalculation in Rank Math's native analysis. PHP templates with empty post content require separate rendered-content review. Use https://rankmath.com/kb/score-100-in-tests/ as the editorial checklist.
